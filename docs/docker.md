# MetriK in Docker (local mode)

Runs the dashboard in a container that reads a `metrics/` folder from the host in **local** mode (server-side reads). It uses Next.js `standalone` output (`output: 'standalone'` in [`next.config.ts`](../next.config.ts)).

## Requirements

- Docker and Docker Compose
- A `metrics/` folder with the JSON files generated by a KaiserInc-Utils boilerplate

## Quick start (docker compose)

```bash
# METRICS_HOST_DIR = ABSOLUTE path on the host to the metrics/ folder
METRICS_HOST_DIR=/abs/path/to/project/metrics docker compose up --build
```

Open `http://localhost:3000` for the landing page, or `http://localhost:3000/dashboard` for the report list.

Compose mounts `METRICS_HOST_DIR` at `/metrics:ro` and sets `METRICS_DIR=/metrics` inside the container. The port is configurable with `METRIK_PORT` (default `3000`).

```bash
METRIK_PORT=8080 METRICS_HOST_DIR=/abs/path/metrics docker compose up --build
```

## Without compose (plain docker)

```bash
docker build -t metrik .
docker run --rm -p 3000:3000 \
  -e METRICS_DIR=/metrics \
  -v /abs/path/to/project/metrics:/metrics:ro \
  metrik
```

## Health check

```bash
curl http://localhost:3000/api/health
# { "ok": true, "mode": "local", "metricsDir": "/metrics",
#   "reportCount": 4, "invalidCount": 1 }
```

`invalidCount > 0` means some reports failed validation. The dashboard shows a notice naming each file and the missing or invalid key.

## Notes

- The container runs as the non-root `node` user.
- The mount is **read-only** (`:ro`), so the dashboard never writes to the folder.
