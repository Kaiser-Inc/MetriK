# MetriK

MetriK is a multi-stack code quality dashboard. It reads the JSON reports generated by the [KaiserInc-Utils](https://github.com/Kaiser-Inc/Utils) boilerplates (Python FastAPI, Node Fastify, Next.js SaaS, Expo/React Native and Ruby on Rails) and shows them as charts you can compare side by side.

The interface is built with [KaiserInc Base](https://github.com/Kaiser-Inc/base-design), the KaiserInc design system, in a dark, light or system theme.

Report schema: [docs/report-schema.md](docs/report-schema.md) · Run in Docker: [docs/docker.md](docs/docker.md) (both in Portuguese)

## Pages

| Route | What it shows |
|---|---|
| `/` | Landing page: what MetriK does, how it works, the usage tutorial, the metrics and a FAQ |
| `/dashboard` | The list of reports, with a stack filter and a checkbox to pick two reports to compare |
| `/report/[slug]` | One report: the metric strip, four charts and the sections of the stack |
| `/compare?a=…&b=…` | Two reports side by side, with the change in each metric and a per-file diff |

The **Como usar** button in the app header opens the same tutorial as the landing page in a side sheet.

## Features

- **Multi-stack.** The stack is detected from the `project` field of the JSON.
- **Stack filter.** One button per stack, with the real logo. The choice is kept in `sessionStorage`.
- **Labels that follow the stack.** The linter (Pylint, Biome or RuboCop) and the security tool (Xenon, pnpm audit or bundler-audit) change with the project.
- **Metric strip.** Average complexity, maintainability, linter score, coverage, tests, estimated bugs and security. Each metric has a "learn more" panel with its scale and a good practice.
- **Four charts.** Cyclomatic complexity, maintainability, coverage and linter issues, with a fixed legend.
- **N/A states.** When a stack does not produce a metric (Halstead and the maintainability index on Rails, for example), the screen says so instead of showing zeros.
- **Comparison.** Two reports side by side, with the change in each metric colored by whether it improved, and a per-file table. Reports from different stacks can be compared.
- **Two data modes.** Local (reads a folder on the server) and deploy (reads the files in the browser). Docker runs the local mode in a container.
- **Themes.** Dark (default), light and system, stored in `localStorage` under `theme`. Charts follow the theme.

## Quick start

### Local mode (development)

```bash
git clone https://github.com/Kaiser-Inc/MetriK
cd MetriK
pnpm install

cp .env.example .env.local
# Edit .env.local and set METRICS_DIR=/absolute/path/to/the/reports/folder

pnpm dev
```

The reports in that folder show up in `/dashboard`. The **Atualizar lista** button reloads the list without restarting the server.

### Docker (local mode in a container)

```bash
METRICS_HOST_DIR=/abs/path/to/project/metrics docker compose up --build
```

The dashboard opens at `http://localhost:3000` and reads the mounted folder as `/metrics:ro`. More options in [docs/docker.md](docs/docker.md).

### Deploy mode (Vercel or any host)

No environment variables are needed. Whoever opens the page picks the reports folder in the browser, and the files are read there, never sent to a server.

```bash
vercel --prod
```

| Browser | Behavior |
|---|---|
| Chrome, Edge | **Selecionar pasta** uses the File System Access API |
| Firefox, Safari | **Selecionar arquivo(s)**: pick the `.json` files one by one |

**Atualizar** reads the selected folder again. The data stays for the session.

## Generating reports

The reports come from the metrics scripts in the [KaiserInc-Utils](https://github.com/Kaiser-Inc/Utils) boilerplates. Every stack writes the same base JSON schema, with the `project` field naming the stack.

### Python FastAPI

```bash
make metrics-install   # installs radon, pylint, xenon, pytest-cov
make metrics           # writes report_YYYY-MM-DD_HHMMSS.json
```

### Node Fastify

```bash
make metrics           # vitest coverage + AST CC/MI + Biome + pnpm audit → JSON
```

### Ruby on Rails

```bash
make metrics           # rspec + flog + SimpleCov + RuboCop + Brakeman + bundler-audit → JSON
```

## Metrics by stack

| Metric | Python FastAPI | Node Fastify | Ruby on Rails |
|---|---|---|---|
| Cyclomatic complexity | radon cc | custom AST | flog |
| Maintainability index | radon mi | custom AST | N/A |
| Test coverage | pytest-cov | vitest --coverage | SimpleCov |
| Linter | pylint (+ ruff) | Biome | RuboCop |
| Halstead | radon hal | N/A | N/A |
| Security | pip-audit (CVEs) | pnpm audit --prod | bundler-audit + Brakeman |
| Complexity thresholds | xenon | none | none |

Fields marked N/A show an explanatory state in the UI. The optional fields (`ruff`, `pip_audit`, `flog_score` and dual coverage) are described in [docs/report-schema.md](docs/report-schema.md). On Python, the security metric reflects `pip_audit`, and `xenon` has its own section for complexity thresholds.

## Comparing reports

1. Open `/dashboard`.
2. Tick two reports in the list.
3. Click **Ver comparativo** in the bar that appears.

Picking a third report replaces the oldest selection.

## Environment variables

| Variable | Description | Required |
|---|---|---|
| `METRICS_DIR` | Absolute path to the folder with the JSON files. When absent, the app runs in deploy mode. | Local mode only |
| `METRICS_HOST_DIR` | (Docker) Path on the host mounted at `/metrics:ro`. | Docker only |
| `METRIK_PORT` | (Docker) Port exposed on the host (default `3000`). | No |

### Health check

`GET /api/health` returns `{ ok, mode: 'local' | 'deploy', metricsDir, reportCount, invalidCount }`. `invalidCount` counts the reports that failed validation in local mode.

## Design system

The components in `components/ui` come from the [KaiserInc Base](https://github.com/Kaiser-Inc/base-design) registry. The `accordion` is the only local addition, because the registry does not have one yet. The visual rules are short: Geist, one violet accent on zinc neutrals, 32px controls, a 6px radius, no gradients and no cards. Sections sit directly on the page and are separated by space and a thin line.

## Development

```bash
pnpm dev        # dev server on http://localhost:3000
pnpm test       # unit and component tests
pnpm lint       # ESLint
pnpm build      # production build
```

The end-to-end tests read the reports in `e2e/fixtures` and start their own server:

```bash
pnpm exec playwright test
```

If Playwright's browser is not installed, point `PLAYWRIGHT_CHROMIUM_PATH` at a Chromium binary.

```
  ui/                         # KaiserInc Base components (plus accordion)
  landing/                    # Sections of the landing page
  tutorial/                   # Tutorial content and the help sheet
  dashboard/                  # Dashboard, report and comparison screens and their parts
  charts/                     # Complexity, maintainability, coverage and linter charts
  icons/                      # Stack logos
  theme-provider.tsx          # next-themes provider
  theme-select.tsx            # Dark, light and system selector
content/
  landing.ts                  # Landing copy
  tutorial.ts                 # Tutorial copy, shared by the landing page and the help sheet
  metric-info.ts              # "Learn more" panels of each metric
lib/
  parseReport.ts              # migrate(): validation, remaps and normalization
  fileSystem.ts               # Reads the JSON files in the browser and keeps them in the session
  compare.ts                  # Summary rows and per-file diff for the comparison
  metricAvailability.ts       # Detects metrics a stack does not produce
  chartTheme.ts               # Chart colors from the theme tokens
types/
  metrics.ts                  # Stack, STACK_META, MetricsReport and related types
e2e/
  fixtures/                   # One report per stack, used by the end-to-end tests
docs/
  report-schema.md            # Full schema and optional fields
  docker.md                   # Running in Docker
Dockerfile                    # Multi-stage build (standalone output)
docker-compose.yml            # Local mode, mounting METRICS_HOST_DIR
```
